# Упростить взаимодействие brumm_tg и backend

## Текущий статус

Обновлено 4 ноября 2026 года. По решению пользователя управление закрытым Telegram-каналом
возвращено к прежней схеме: приглашения и исключение выполняет backend напрямую.
Кнопка «Упражнения на площадке ГАИ» сохранена. Очередь заданий, аренды, отдельный consumer
и переключатели доставки удалены. Остальной рефакторинг сохранён.

Основание для анализа — доступный локальный снимок репозиториев GitHub:

- `brumm_backend` → `BRUMB4144/gusev_new`, `main` / `origin/main`: `0006b60`.
- `brumm_tg` → `BRUMB4144/brumm_tg`, `feat/telegram-platform-migration` /
  `origin/feat/telegram-platform-migration`: `35e1bc3`.

Изменения реализации находятся в рабочем дереве. Актуальность удалённых веток GitHub и
production-конфигурации отдельно не подтверждена.

Учтены изменения backend: постоянная синхронизация AppMetrica Logs API/DataStream,
диагностика состояния, удаление партнёров с сохранением истории и диагностика отказов входа.
Партнёрская синхронизация остаётся в backend со своим состоянием и арендой; её механизм
не относится к доступу в Telegram-канал. Подробности — в [документации партнёрки](../../brumm_backend/docs/partners.md).

## Разделение ответственности

| Компонент | Ответственность |
|---|---|
| Backend | Пользователи, платежи, подписки, права, рефералы, проверка initData, партнёрская атрибуция, приглашения и исключение из закрытого канала |
| Bot worker | Команды, диалоги админского бота, рассылки, управление PRO через закрытый API |
| Mini App | Интерфейс, состояние запросов, хранение и обновление сессии |

Бот получает бизнес-данные через закрытый API и не подключается к MongoDB.
Username Telegram хранится в backend и обновляется из проверенного initData и команды `/start`.
Получение username не требует внешнего запроса к Telegram.

## Реализованные изменения

### Сессия и запросы Mini App

- [x] Общий модуль сохраняет access и refresh token при входе и обновлении сессии.
- [x] Параллельные 401 используют один запрос refresh; запоздалый 401 повторяется с актуальным токеном.
- [x] Сетевая ошибка refresh сохраняет сессию, подтверждённый отказ авторизации очищает её.
- [x] Сервисы передают ошибки вызывающему коду; UI показывает ошибки запросов.
- [x] Для профиля и уведомлений добавлена повторная загрузка, запрос уведомлений общий для компонентов.
- [x] Отсутствие соседнего урока на границе курса возвращает null; ошибки сети и отсутствующего курса остаются ошибками.

### Telegram-профиль и взаимодействие с backend

- [x] Username берётся из подписанного initData; админские списки читают его из MongoDB.
- [x] Фильтрация пользователей и подсчёт результатов выполняются до пагинации, без запросов Telegram на каждую строку.
- [x] `/start-events` вызывается при каждом `/start`, поддерживает отсутствие deep link и явную очистку username через null.
- [x] `/start-events` обновляет существующий профиль без создания учебного аккаунта; ошибки записи возвращаются API.
- [x] Бот отвечает приветствием и при ошибке учёта перехода.

### Закрытый канал и устройство worker

- [x] Восстановлены прямые вызовы backend для приглашения и исключения из канала; сохранены условия выдачи доступа.
- [x] Приглашения после оплаты, промокода и административной выдачи PRO отправляются после сохранения пользователя.
- [x] Кнопка «Упражнения на площадке ГАИ» открывает прежнюю ссылку.
- [x] Удалены очередь канала, её поля/индекс, endpoints, consumer, режим legacy и переменные переключения.
- [x] Админский бот разделён на маршрутизацию, управление PRO, черновики и диалог рассылки.
- [x] Убраны сервисы-переэкспорты; остановка worker ожидает текущую работу рассылки в пределах таймаута.

Схема и настройки доступа описаны в [инструкции приватного канала](telegram-channel-access.md).

## Проверка и выкладка

Перед выкладкой выполнить `npm test` в обоих репозиториях и `npm run build`, `npm run lint`
в `brumm_tg`. Проверить вход, два последовательных обновления сессии, параллельные 401,
крайние уроки курса, оплату, промокоды, кнопку упражнений и административные команды.

В текущей среде HTTP-тесты, открывающие локальный порт, ограничены ошибкой `listen EPERM`.
Они должны пройти перед выкладкой в среде, разрешающей локальный HTTP. Production-переключение
и проверка настоящего Telegram-канала в рамках локальной реализации не выполнялись.

Специальное переключение доставки или миграция очереди не требуются: backend сохраняет прежние
настройки канала. Порядок запуска ботов и Mini App — в [инструкции развёртывания](deployment-migration.md).

## Ограничения

Сохраняются два репозитория, существующая MongoDB и один polling-процесс.
Фоновое закрытие доступа к каналу по сроку PRO, восстановление рассылок после рестарта и
защита от гонок параллельных платёжных callbacks остаются отдельными задачами.
